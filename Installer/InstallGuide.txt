FactoryX Radio DJ - binary installation

Requirements: x64 Windows 10/11 or Windows Server with Windows Media Foundation,
an interactive desktop and working audio devices for the mixer. RDJ and RDJ Pro
are desktop applications; FxServe and FxRecord can run unattended as services.
On Server, install Media Foundation through Server Manager if it is absent.
Users do not need Delphi, MfPack sources or design-time components.

Choose workstation, server or combined installation. Custom lets you select RDJ
(audio), RDJ Pro (audio/video), server, recorder, admin tools and Icecast.
The two mixers have separate folders and settings. First launch opens setup.
Choose audio devices and configure recording and broadcast paths there.
The library database and settings are created on first use; no personal music,
database, device settings, password or live recording is included in Setup.

LOCAL: install combined components on your PC. FxServe binds to localhost.
LAN: install server components on the Windows server, workstation components
on the studio PC. FxServe listens on port 8080. Use local paths on the server.
Configure an authenticated SMB share for the studio publisher and give only
its publishing account write access to FxServe\www. On RDJ Pro, select the
corresponding UNC paths for Stream, Artwork and nowplaying.json. Use a separate
share/access policy for recorder administration. Services use local paths.

WAN: install server components on the destination Windows host. Supply your
real DNS hostname in Setup, point its DNS to the server and forward inbound
TCP 80 and 443. Use FxServe Admin to verify HTTPS/certificates and WAN settings.
Keep TCP 80 reachable for ACME validation. Configure publication over a private
VPN or the application's supported authenticated upload/mirroring workflow.
Do not expose SMB or administrative service control directly to the Internet.
Setup cannot configure your router, DNS, VPN or remote account permissions.

SERVICES: configuration is written during Setup. On the tasks page you can
optionally register/start services and open the selected network firewall ports.
For recorder-only installations, leave startup unchecked until you configure
the actual stream folder. To install services later, open elevated PowerShell:

  cd C:\FactoryXRadioDJ\Scripts
  .\Configure-Server.ps1 -InstallRoot C:\FactoryXRadioDJ -NetworkMode LAN -ConfigureFxServe -InstallServices -OpenFirewall

For WAN add -NetworkMode WAN -PublicHostname radio.example.com (replace LAN).
For the recorder add -ConfigureFxRecord after reviewing FxRecord\FxRecord.ini.
Only select ConfigureFxServe/ConfigureFxRecord for components installed here.
Service installation uses native executable switches and logs failures.
Recorder defaults to SourceCopy, which avoids background audio conversion.
If the stream is hosted elsewhere, edit StreamPath to its local server folder.
FxRecordAdmin manages the service/settings; it does not run the recorder itself.
FxRecord must run on the host with local access to the published stream files.

RDJ audio streaming requires Icecast. Select the bundled installer, then choose
Install Icecast on Setup's final page. Configure its passwords and /live mount
using the RDJ user manual. FxServe proxies local Icecast port 8000.
Caddy archives are an optional alternative; extract the matching RDJ/Pro archive
and caddy.zip, then configure Caddy using the supplied manuals. Stop FxServe
before using Caddy on ports 80/443.

UPGRADES AND REMOVAL: stop FxServe/FxRecord and close the mixers/admin tools
before upgrading. Existing INIs and user data are preserved. Back up Data and
recordings before upgrades. Do not install over a running service from another
folder. Before uninstalling, stop and unregister services using their matching
executables --uninstall or FxRecord's Uninstall-FxRecord.cmd. Remove firewall
rules you created with Remove-NetFirewallRule -Name FactoryX-RDJ-LAN or
FactoryX-RDJ-WAN. Setup does not delete databases, logs or recording archives.

This candidate uses the supplied precompiled mixer builds. BuildManifest.json
records exact timestamps, sizes and SHA-256 hashes. Run a clean-machine audio,
video, LAN and WAN acceptance test before public release. Future packages should
use freshly compiled release binaries. The package is not digitally signed.
